# 升级与备份

## 版本号规则

`主版本.次版本.修订号`。数据库结构的变化只发生在次版本或主版本，修订号永远是兼容的。

判断能不能直接升，看两件事：

1. **CHANGELOG 里有没有标注「不能直接升级」**
2. 备份文件里的 `vN` 是否等于当前的 `schemaVersion`（设置 → 数据里能看到）

## 桌面端升级

覆盖安装到**同一个目录**即可。`data/` 会原地保留。

```
ToolBox/
  toolbox-desktop.exe
  data/
    local.db                  ← 数据库
    local.db.v2-*.bak         ← 升级前自动备份
    known_hosts.json          ← SSH 主机指纹
    window_state.json         ← 窗口大小与位置
    logs/app.log              ← 日志（5MB 轮转，保留一份）
```

升级前建议手动复制一份 `data/`。成本几秒，收益是万一出问题不用慌。

## Docker 升级

```bash
# 1. 备份（多一层保险）
cp -r docker/data docker/data.backup-$(date +%Y%m%d)

# 2. 更新并重建
git pull
cd docker && docker compose up -d --build
```

`data/` 是挂载卷，重建容器不动它。

如果启动失败，看日志：

```bash
docker compose logs toolbox | tail -50
```

## 自动备份

**只要数据库结构需要变化，升级前就会自动备份一份。** 平时启动不产生备份。

备份文件与数据库同目录，命名规则：

```
local.db.v2-2026-11-02T11-30-00.bak
└─┬──┘ └┬┘ └──────┬──────┘
 库名  版本     创建时间
```

版本号是备份时的 schema 版本，一眼能看出这份数据来自哪个结构。

**备份永不自动删除**，所以长期使用会堆积。在「设置 → 数据」里可以逐个删。

## 手动备份与回滚

进入 **设置 → 数据**。

### 立即备份

随时存一份当下状态。适用于：改重要配置前、试新功能前。

### 恢复

点某个备份旁的恢复按钮，**需要输入 `RESTORE` 确认**。

恢复会：

1. 先给当前数据存一份安全副本
2. 用选定备份覆盖数据库
3. 强制退出登录（会话表也被替换了）

```
恢复前                         恢复后
─────────────────────────────────────────
local.db                       local.db（来自备份）
local.db.v2-10-15.bak          local.db.v2-10-15.bak
                               local.db.v2-11-02.bak  ← 安全副本
```

安全副本的意义：万一选错了备份文件，它还在。

### 下载

把备份存到别处。网页端走浏览器下载，桌面端弹保存对话框。

## 结构版本

数据库用 SQLite 内置的 `PRAGMA user_version` 记录结构版本。三条保证：

| 保证                 | 机制                                   |
| -------------------- | -------------------------------------- |
| 迁移失败不留半截结构 | 每个迁移在独立事务里，失败即回滚       |
| 出问题可回退         | 升级前自动备份，文件永久保留           |
| 降级不损坏数据       | 库版本高于程序时**拒绝启动**并明确提示 |

最后一条值得展开：如果误装了旧版本，程序不会「尽力而为」地读一个结构未知的库——它会停下来告诉你为什么。

## 从 2.0.0 之前的版本升级

**不行。** 2.0.0 是彻底重写，数据结构完全不同，也没有迁移工具。

如果 1.x 里有想保留的 SSH 服务器配置，请先手动记下，装好新版后重新添加。

## 出问题了

### 升级后打不开

1. 看日志：桌面端 `data/logs/app.log`，Docker 用 `docker compose logs`
2. 如果是迁移失败，错误信息里会写明备份文件路径
3. 把备份重命名为 `local.db` 即可回退

### 数据库版本过高

报错类似「数据库版本为 5，高于当前程序支持的 4」。

说明装回了旧版本。要么升级到新版，要么从给新版本做的备份恢复。

### 想彻底重来

删掉 `data/local.db`。所有数据（账号、服务器、设置）都会清空，下次启动重新注册。
