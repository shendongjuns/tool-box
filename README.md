## 缘起

我们每天都在跟一堆零碎小工具打交道。格式化一段 JSON、转一次 Base64、算个哈希、看一眼某个服务跑了多久。

这些事都不难。麻烦的是它们散落在各处——十几个网页、几本书签、几个记不清名字的在线服务。更麻烦的是，当你把一段生产环境的数据贴进某个随机弹出的网站时，你并不真的知道它去了哪里。

ToolBox 想做的，是把这些小事收进一个安静的地方。

它没有账号体系，没有订阅，没有遥测。装在自己的电脑上，或者自己的服务器上。打开它就干活，关上它就走。数据留在原处，不经过任何人。

## 它能做什么

同一套房子的两个门。你可以从浏览器进去，也可以双击桌面上那个图标。

**编码** 里住着六件常备的器具：JSON 格式化、Base64、URL 编解码、时间戳转换、哈希、UUID。都是些一眼就懂、拿来就用的小东西，不需要读文档。

**远程** 是后来加的一间屋子。把服务器添进去，同一扇窗里就能看到终端、文件、还有机器的心跳——CPU 的呼吸、内存的余量、磁盘的空地、几张显卡各自忙到什么程度。

如果你恰好有华为昇腾的机器，它也会认出那些 NPU，把算力画成曲线。

## 开始使用

需要 Node.js 22.12 以上、pnpm 11。

```bash
git clone https://github.com/shendongjuns/tool-box.git
cd tool-box
pnpm install
pnpm dev
```

然后打开 <http://localhost:5173>。第一次见面，它会请你创建一个账号——这是这座房子唯一的钥匙，此后不再需要第二把。

## 安放与携带

### 放在自己的服务器上

```bash
cd docker
docker compose up -d --build
```

它只负责在自己门口挂一盏灯，不操心域名、证书、隧道——那些交给你的反向代理。

默认只对这台机器开放。想让同一局域网里的其它设备也进来，把 `compose.yml` 里那行端口映射的 `127.0.0.1:` 去掉即可。

启动时它会把局域网地址打印出来，照着填就行。

### 带在身边

Windows 上有一个约 3.6MB 的安装包，也有一个解压即用的压缩包。

所有东西都放在程序旁边的 `data/` 目录里——数据库、窗口大小、日志，一个文件夹就是全部。想搬走，整个文件夹拷走；想重来，删掉它。

关机、断网、换台机器，都不影响你手里这份数据。

## 它的性格

**只住一个人。** 这座房子只有一个住户名额。第一次创建账号之后，门就关上了。

**本地与云端各过各的。** 桌面端可以同时记着本机和几台远程服务器的地址。它们的数据互不相干，切换只是换一扇门进去，不存在同步，也不会互相覆盖。

**关窗只是拉上窗帘。** 点右上角的叉，它退到托盘里待着，不问你确认。真要离开，右键托盘图标选退出。

**三十天不用重新开门。** 用着用着它自己续期；改了密码，其它地方的登录会一起失效。

## 升级

**2.0.0 是从零重写的**，和 1.x 之间没有代码或数据上的延续——它不是升级版，是另起一行。所以从 1.5.0 过来的话，需要重新安装、重新添加服务器。旧版里的东西请先手动记下。

2.0.x 内部的小版本（2.0.1、2.0.2……）可以**直接覆盖安装**：只新增表，不改已有字段，老数据自动沿用。

覆盖安装前做一件事——把 `data/` 整个目录复制一份。装到同一个位置，数据就还在。

服务端更简单，`data/` 是挂载卷，重建容器不碰里面的东西。

每个版本具体改了什么、能不能直接升，记在 [CHANGELOG](CHANGELOG.md) 里。

## 常见疑问

<details>
<summary><b>忘记密码了</b></summary>

单用户系统没有找回的路——这正是它的设计。

停掉服务，清掉数据库里 `users` 和 `sessions` 两张表的数据，重新打开就能重新建号。你的其它数据都还在。

- 桌面端：`data/local.db`
- 服务端：`docker/data/toolbox.db`

</details>

<details>
<summary><b>能开第二个账号吗</b></summary>

不能。这是刻意的。
</details>

<details>
<summary><b>本地和云端的数据会同步吗</b></summary>

不会。它们各自独立，切换只是换个连接，不存在合并或覆盖。
</details>

<details>
<summary><b>能从 1.5.0 升级吗</b></summary>

不能。2.0.0 是彻底重写，数据结构完全不同，也没有迁移工具。

如果旧版里有想保留的服务器配置，请先记下来，装好新版后重新添加。
</details>

<details>
<summary><b>升级后数据会丢吗</b></summary>

同为 2.0.x 版本之间不会——覆盖安装不动 `data/` 目录。

但保险起见，升级前请把 `data/` 复制一份。数据库结构一旦变更，退回旧版本可能读不了新数据。
</details>

<details>
<summary><b>Windows 11 任务栏里找不到它</b></summary>

系统默认把新图标折叠起来。点右下角那个 `^`，或者到「设置 → 个性化 → 任务栏 → 其他系统托盘图标」里打开。
</details>

<details>
<summary><b>打包桌面端时报「拒绝访问」</b></summary>

程序正在运行，先退出再打包。
</details>

## 关于安全

说几句实在话：

密码用 Argon2id 保存，不存明文，也不限制你用什么字符。会话令牌只存摘要。桌面端连远程服务器用的密码和私钥，落盘前会加密。

这些措施能挡住「拿到数据文件」的人。但如果有人已经能在你的电脑上以你的身份运行程序，任何纯本地的加密都挡不住——钥匙终究要由程序自己算出来。这是本地存储的边界，不是实现上的疏忽。

想再稳一点，就把服务放在反向代理后面，加上 HTTPS。

## 如果你也想改点什么

代码分三层：`apps/` 是应用（服务端、网页端、桌面壳），`packages/` 是共享的约定与数据层，`docker/` 是部署。

常用的命令：

```bash
pnpm dev        # 起开发环境
pnpm build      # 全量构建
pnpm test       # 跑测试
pnpm typecheck  # 类型检查
pnpm lint       # 代码检查
```

想加一件新工具，只需要在 `packages/contracts/src/tool-catalog.ts` 里登个记，再写一个组件——侧栏、路由、搜索会自己认识它。

提交之前，请让 `pnpm lint && pnpm test && pnpm typecheck` 都亮绿灯。
